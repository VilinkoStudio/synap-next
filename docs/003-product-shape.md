# 003 产品形态

这里只谈软件打开之后是什么感觉、界面与插件之间怎么划边界。存和算见 [002 架构](002-architecture.md)。

## 一、一切 UI 皆投影：给独立页面，但不造孤岛

过去曾想过把所有功能都塞进一个“主工作区 + 侧边栏槽位”里，避免做成一堆小应用。但真实使用中，刷一套题、排一个看板、浏览双链图谱、管理待办清单，天生就需要完整的独立页面和专属交互空间，硬塞进侧边栏只会处处掣肘。

所以我们**明确允许 UI Plugin 拥有完整的独立页面**。它之所以不会退化成“微信小程序”，区别不在有没有独立页面，而在底层：

* **小程序是数据孤岛：** 每个小程序各自建库，装十个插件就是十个互相隔绝的盒子，内容跳不过去。
* **这里每个页面只是同一池子数据的不同切面（投影）：** 待办页、笔记页、复盘页订阅的是同一个底层数据内核的不同 Projection。

由此带来两条最核心的交互原则：

1. **导航栏钉住的是常用视图，不是应用图标：** 桌面端侧栏或手机端底栏放的是用户自己钉住的高频投影页面（如收件箱、待办、笔记、专项视图），随时可增删排序。
2. **实体可以跨视图自由穿行：** 同一个 Entity 可以同时出现在多个投影里。点开它时，宿主默认用最匹配的 UI Plugin 呈现；同时提供轻量的“切换视角（Lens）”入口，列出所有支持它当前 Trait 的其他视图，随时无损切换，不把人困在某一个页面里。

## 二、数据与视图彻底解耦带来的两种常态

因为 Data Plugin 和 UI Plugin 彼此独立，系统天然支持两种非常舒服的工作形态：

* **有数据，不展示（幕后数据）：** 并不是所有存进数据库的东西都要做界面。比如遗忘曲线参数、知识点掌握度、外部同步进来的原始元数据，它们只需要作为 Data Plugin 静默躺在底层，参与响应式计算、影响投影排序即可，完全不污染前台界面。
* **同源多视图（一数多景）：** 同一批底层数据，可以同时挂接多个完全不同的 UI Plugin。比如同一份错题集，平时复习时用“卡片刷题页”，考前复盘时切到“错因统计页”，互不干扰且状态实时联动。

## 三、端侧解耦：放弃单插件跨端，用通用视图兜底

要求一个轻量插件同时把桌面横屏和手机竖屏都排得顺手，开发成本极高，结果往往是两边都别扭。

因此本项目**暂时放弃“单插件自动跨全端”的幻想**，定下更务实的策略：

* **单插件只专注一个端形态：** 每个 UI Plugin 明确声明自己面向横屏（桌面）还是竖屏（手机），把当前屏幕的交互做到位即可。如果某个高频场景（如待办）两端都要重度使用，就分别配一个极简的竖屏插件和一个丰富的横屏插件，它们订阅同一条底层投影，数据天然同步。
* **缺插件时的优雅降级：** 当你在电脑上用某个横屏插件写了数据，出门掏出手机却没装对应的竖屏插件时，数据不会“打不开”。宿主内置一套**通用 Trait 视图**，能够根据该实体暴露的 Trait（如 `HasText`、`Checkable`、标签、时间等）自动渲染出干净的只读/基础编辑界面，保证在任何设备上永远可读、可查、可改基础状态。

## 四、美学与自由的边界：布局自由，零件受控

既要给插件足够大的表现空间，又要防止装了五六个插件后整个软件风格割裂、丑陋难用，边界划在“布局归插件，零件归宿主”：

* **插件拥有画布和排版权：** 插件决定这一页是两栏、三栏、瀑布流、卡片堆叠还是答题流，自己组织页面内的交互流转。
* **宿主锁死设计系统：** 字体排版、配色体系、暗黑模式、圆角间距以及基础交互组件（列表、卡片、输入框、按钮、弹窗、Markdown 渲染块、标签等）全部由宿主统一提供和规范。插件只用宿主给的零件搭页面，不自己写底层样式调像素。

这样既保住了插件的创作空间，也把整个软件的视觉下限死死托住。

---

## 五、宿主保持克制：不内置 AI，做好底座

本项目**不把大模型对话框做成主页，也不在客户端里内置 AI 聊天或重型 Agent Harness**。

大模型与 Agent 工具迭代极快，把它们写死在客户端里只会让软件迅速臃肿过时。我们的分工非常明确：

* **外部 AI 负责生产与编排：** 借助 Rust 内核暴露的标准结构化接口，外部 AI 工具可以安全地读取个人知识库、生成结构化数据（如复习试卷、整理卡片），甚至按用户需求编写新的 Data Plugin 或 UI Plugin。
* **宿主只负责稳健呈现：** 宿主保持纯粹，专注于把投影渲染流畅、把组件库打磨顺手，并支持顺滑地加载与切换视图插件。

---

## 六、零插件也能用，卸插件不留坑

即使一个额外插件都不装，官方宿主本身依然是一个完整可用的个人数据工作台：

* 内置基础的通用 Trait 视图、全局搜索、快速记录、冲突解决中心（订阅 `trait.Conflict`）以及本地文件导入导出。
* 第一方内置视图与第三方 UI Plugin 走完全相同的投影与 Trait 接口，不搞特权通道。
* 任何 UI Plugin 卸载后，底层数据毫发无损，对应实体自动回退到通用 Trait 视图展示，不留下损坏的入口或死链；同样，任何 Data Plugin 归档禁用后，历史数据依然永远可读。
